# Extract Subtitles (PgsToSrtPlus)
- Extracts subtitles for the requested languages. Text subtitles are extracted via ffmpeg; PGS (image-based) subtitles are OCR'd to SRT — by default only when no non-commentary text subtitles exist for a given language.
- Writes the same `_subtitles.exports` manifest as the other subtitle plugins, so it slots into the `buildDv81Mp4` / `buildDv81Mp4Ffmpeg` pipeline.
- Inputs:
  - `PgsToSrtPlus Run Command` (string, default empty): command to run PgsToSrtPlus, e.g. `docker run --rm -v /media:/media ebette1/pgs-to-srt-plus:latest`. If empty, PGS OCR is skipped and only text subtitles are extracted.
  - `Languages` (string, default `eng`): comma-separated ISO 639-2 codes.
  - `Ollama URL` / `Ollama Model` (strings): passed to PgsToSrtPlus via `--ollama` / `--model` for VLM-based OCR fallback.
  - `Skip PGS When Text Exists` (boolean, default `true`): skip OCR for a language when non-commentary text subtitles already exist.
  - `Extract All PGS Per Language` (boolean, default `false`): OCR every PGS track per language instead of forced tracks + first main track.
  - `Prefer Text Subtitle as Default` (boolean, default `true`): transfer the default flag from an image-based subtitle to a same-language text subtitle.
  - `Output Directory` (string, optional; defaults to Tdarr cache).
  - `Preserve Stream Metadata` (boolean, default `true`).
- Default/disposition flags are read from the original library file (not Tdarr's working copy) to avoid ffmpeg's artificial `default=1` on intermediate remuxes.

## Dependency: PgsToSrtPlus (required for OCR)

This plugin **strictly depends on [PgsToSrtPlus](https://github.com/eebette/PgsToSrtPlus/tree/master)** for PGS OCR. It is not installed by the Install DV Tools plugin — you must provide a working run command yourself. Without it, only text subtitles are extracted. PgsToSrtPlus also requires a reachable [Ollama](https://ollama.com) API endpoint for its VLM-based OCR (`Ollama URL` / `Ollama Model` inputs).

The simplest way to run it is the Docker image (`ebette1/pgs-to-srt-plus`). When Tdarr itself runs in Docker, that means Docker-in-Docker: the Tdarr container needs a `docker` CLI and a daemon to talk to, and the media paths must resolve identically inside the OCR container.

### Reference setup: docker:dind sidecar

Known-working Compose pattern (trimmed to the relevant parts):

```yaml
services:
  tdarr:
    image: ghcr.io/haveagitgat/tdarr:latest
    depends_on:
      - dind
    environment:
      - DOCKER_HOST=tcp://127.0.0.1:2376
      - DOCKER_TLS_CERTDIR=/certs
      - DOCKER_CERT_PATH=/certs/client
      - DOCKER_TLS_VERIFY=1
    volumes:
      # Static docker CLI binary (download from https://download.docker.com/linux/static/stable/)
      - /etc/docker/tdarr/docker-bin/docker:/usr/local/bin/docker
      # TLS client certs generated by the dind container
      - /etc/docker/dind/certs:/certs:ro
      - /path/to/media:/media

  dind:
    image: docker:dind
    privileged: true
    environment:
      DOCKER_TLS_CERTDIR: /certs
    volumes:
      - /etc/docker/dind/certs:/certs
      - /etc/docker/dind/docker:/var/lib/docker
      # Same media path as the Tdarr container — REQUIRED
      - /path/to/media:/media
```

How the pieces fit:

- The `dind` sidecar runs a full Docker daemon (`privileged` is required) and auto-generates TLS certs into the shared `/certs` volume on first start.
- The Tdarr container gets a static `docker` CLI bind-mounted in, and the `DOCKER_HOST`/`DOCKER_CERT_PATH`/`DOCKER_TLS_VERIFY` environment points it at the dind daemon over TLS.
- `DOCKER_HOST=tcp://127.0.0.1:2376` works when both containers share a network namespace (e.g. both use `network_mode: container:<vpn>` behind a VPN container). If they are on a regular shared Compose network instead, use the dind service's hostname.
- The media volume must be mounted at the **same path** in both containers: the plugin passes file paths from Tdarr's point of view, and the OCR container spawned by dind resolves them against dind's own mounts. `-v /media:/media` in the run command then maps them 1:1.
- OCR containers spawned this way run inside dind's isolated `/var/lib/docker`, so they never touch the host daemon.
